# Go Runtime 图标总设计规范

本规范适用于 `developer_library/golang/runtime` 下 GC、GMP、Memory、Scheduler 四个子库中新建或修改的 Excalidraw 图标。各子库 README 的“图标规范”章节是本规范的补充；两者冲突时，以子库规则为准。

## 1. 画布与通用样式   

- 每个 library item 按名义 `80 × 80` 画布设计，图形实际占用范围保持在约 `40–60 px` 宽、`34–61 px` 高；内容在视觉上居中。
- 所有轮廓、内部结构线和箭头使用 `#1f2937`、`2 px`、实线、`roughness: 1`。
- 形状使用 `fillStyle: solid`；默认主填充使用低饱和色，细节可使用 `#ffffff`，连接线、箭头和文字背景必须透明。
- 图标内文字使用 font family 1、`#111827`、水平与垂直居中。默认字号为 `11 px`；紧凑或长标签可降至 `9–10 px`；圆形中的一至两个字符可使用 `13 px`。
- 不使用渐变、高光、阴影、外部 Logo、照片、拟物纹理或超过两层的内部装饰。

## 2. 形状语义

| 结构 | 表示含义 | 使用规则 |
| --- | --- | --- |
| 圆形/椭圆 | 事件或等待节点 | 用于 Netpoll、Timer、sudog 等具有触发或等待语义的概念；GMP 对象的具体形态由其子库专项规范定义。 |
| 矩形 | 队列、描述符、内存容器或分配层级 | 用于 Queue、Heap、Span、Page、pollDesc 等有边界的数据结构。 |
| 内部直线 | 分层、槽位或内部结构 | 仅用于表达结构层次；不可作为额外装饰。 |
| 内部箭头 | 图标内部的循环、调度或生命周期方向 | 仅在语义需要时使用，例如 GC 或 Scheduler；跨图标关系由使用图的连线表达。 |

## 3. 颜色与文字

- 主填充色是图标的身份色，现有 20 个图标不得互换或复用为其他语义。
- 新增图标应从现有色板中选择未占用的低饱和色；若确需复用颜色，必须表示同一概念的变体，并在所属 README 中说明。
- 描边和文字颜色固定，不得随填充色改变；仅在图标内部需要分区时使用白色细节。
- Library 内只保留必要缩写；catalog 和 README 必须补充完整名称与中文用途说明。

## 4. Library 与 Catalog

- 每个图标在 `.excalidrawlib` 中是独立 item，所有组成元素保持同一图标组。
- 每个 `.excalidraw` catalog 都必须包含标题、图标、完整名称和用途说明；图标按五列网格排列，列间距 `170 px`、行间距 `150 px`。
- Catalog 标题位于 `x=40, y=16`；首行图标的最小坐标从 `x=4, y=92` 开始。
- 新增或改名图标时，同步更新同目录的 library、catalog、README 和颜色登记。

## 5. 验收清单

- 图标使用规定的描边、线宽、粗糙度、文字色和纯色填充。
- 图形尺寸、形状语义、文字字号符合总规范和所属子库规范。
- 主填充色与现有图标不冲突，且在 README 中可追溯。
- library 与 catalog 的图标、名称和说明一一对应，相关 JSON 可解析。
- 提交前执行 `git diff --check`，并在 Excalidraw 中确认缩写可读、未被裁切。
