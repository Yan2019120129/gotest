# 密码哈希算法用例

汇总常见的密码哈希 / 派生算法测试用例，按算法分文件夹存放，每个文件夹内为 `index.go`。

| 算法 | 常见分类 | 实现状态 |
|------|----------|----------|
| [bcrypt](bcrypt/index.go) | 自适应密码哈希函数 | 已实现 |
| [Argon2id](argon2id/index.go) | 内存困难型密码哈希函数 | 已实现 |
| [scrypt](scrypt/index.go) | 内存困难型密码派生函数 | 已实现 |
| [PBKDF2](pbkdf2/index.go) | 基于迭代次数的密码派生函数 | 已实现 |
| [SHA-256](sha256/index.go) | 通用哈希函数，不适合直接存密码 | 已实现 |

说明：bcrypt / Argon2id / scrypt / PBKDF2 四个用例依赖 `golang.org/x/crypto`，SHA-256 / MD5 仅使用标准库。

## 算法详解

> 💡 **快速选型**
>
> - **新项目** → 🛡️ **Argon2id**：安全性最高，抗 GPU/ASIC 并行破解
> - **存量系统 / 兼容优先** → 🔐 **bcrypt**：生态成熟，可逐步升级 cost
> - **加密钱包 / 密钥派生** → 🧠 **scrypt**：内存困难型 KDF
> - **FIPS 合规环境** → ⏳ **PBKDF2**：标准成熟，需保证高迭代次数
> - ⚠️ **MD5 / SHA-256** 只做摘要与完整性校验，**禁止用于密码存储**

---

### 🛡️ Argon2id — 内存困难型密码哈希

> **定义**：2015 年密码哈希竞赛冠军，RFC 9106 标准，当前安全性最高的密码存储方案。

- **核心作用**：生成带随机盐、高计算成本、高内存消耗的密码哈希
- **解决的问题**：防御 GPU/ASIC 大规模并行破解，抬高攻击者硬件成本
- **基本原理**：`BLAKE2b 初始化 → 多线程内存块填充 → 多轮计算 → XOR 合并`，参数 `memory / time / parallelism`
- **API**：`argon2.IDKey()` · 盐 `crypto/rand.Read()` · 比较 `subtle.ConstantTimeCompare()` · 常见参数 `m=64MiB, t=1, p=4`
- **适用场景**：新系统密码存储、高安全认证、金融系统

✅ **优点**：抗 GPU/ASIC 最强 · 安全性最高 · 参数可升级 · 标准化程度高
⚠️ **风险**：参数过低削弱安全性 · 高并发可被资源消耗攻击 · 不能解决弱密码
❗ **限制**：内存占用较高 · 计算成本较高 · 移动端需降低参数 · 生态兼容性不如 bcrypt
🔁 **替代**：bcrypt（兼容优先）、scrypt

> [!TIP] 新项目密码存储的**首选**。

---

### 🔐 bcrypt — 自适应密码哈希

> **定义**：基于 Blowfish 设计的自适应密码哈希算法，专用于密码存储。

- **核心作用**：生成不可逆密码哈希，提高密码离线破解成本
- **解决的问题**：防止数据库泄露导致密码明文暴露，用 salt + cost 对抗彩虹表与暴力破解
- **基本原理**：`密码 → 随机 salt → 设置 cost → Blowfish 扩展密钥计算 → $2a$cost$salt$hash`
- **API**：`bcrypt.GenerateFromPassword()` 生成 · `bcrypt.CompareHashAndPassword()` 校验 · 核心参数 `cost`（默认 10）
- **适用场景**：用户登录密码存储、账号认证系统

✅ **优点**：生态成熟 · 兼容性强 · 支持逐步升级 cost
⚠️ **风险**：哈希泄露后仍可离线破解 · GPU 并行优势明显 · 弱密码易被字典攻击 · cost 过高可致 DoS
❗ **限制**：仅 CPU 困难、无内存困难 · 高并发登录增加 CPU 压力与接口延迟 · 安全性低于 Argon2id
🔁 **替代**：Argon2id（推荐）、scrypt

> [!NOTE] 存量系统与兼容场景的**默认选择**。

---

### 🧠 scrypt — 内存困难型密码派生函数

> **定义**：通过大量内存访问提高破解成本的内存困难型 KDF。

- **核心作用**：生成高成本密码派生密钥，提高离线破解难度
- **解决的问题**：降低 GPU/ASIC 并行计算优势，抵御密码暴力破解
- **基本原理**：`密码 + salt → PBKDF2 初始化 → ROMix 大规模内存计算 → PBKDF2 输出密钥`，参数 `N / r / p`
- **API**：`scrypt.Key()` · 随机盐 `crypto/rand.Read()` · 推荐参数 `N=32768, r=8, p=1`
- **适用场景**：密码存储、加密钱包、密钥派生

✅ **优点**：抗 GPU 能力强 · 设计成熟 · 比 bcrypt 更安全
⚠️ **风险**：参数过低容易破解 · 高并发可能造成内存压力 · 实现不当存在侧信道风险
❗ **限制**：内存消耗较大 · 参数需根据硬件调优 · 综合性能不如 Argon2id
🔁 **替代**：Argon2id（推荐）、bcrypt

> [!NOTE] 加密钱包与密钥派生的**成熟选择**。

---

### ⏳ PBKDF2 — 基于密码的密钥派生函数

> **定义**：RFC 8018 标准，通过大量迭代增加密码计算成本。

- **核心作用**：通过大量迭代增加密码计算成本
- **解决的问题**：降低暴力破解速度，避免密码直接哈希存储
- **基本原理**：`密码 + salt → HMAC 计算 → 多轮迭代 → 输出固定长度密钥`，核心参数为迭代次数
- **API**：`pbkdf2.Key()` · 推荐 `HMAC-SHA256`、`600000` 次迭代、32 字节输出
- **适用场景**：企业认证系统、FIPS 合规环境、传统系统

✅ **优点**：标准成熟 · 兼容性最好 · 支持 FIPS
⚠️ **风险**：迭代次数不足容易破解 · 无法抵御现代 GPU 集群攻击
❗ **限制**：不消耗内存 · GPU 并行优势明显 · 安全性低于 Argon2id
🔁 **替代**：Argon2id、scrypt

> [!NOTE] FIPS 合规环境的**兜底方案**。

---

### ⚡ SHA-256 — 通用哈希算法

> **定义**：SHA-2 系列密码学哈希算法，输出 256 bit 固定摘要。

- **核心作用**：数据摘要、完整性校验、数字签名基础
- **解决的问题**：检测数据是否被修改，保证数据一致性
- **基本原理**：`数据填充 → 512 bit 分组 → 64 轮压缩计算 → 输出 256 bit 摘要`
- **API**：`sha256.Sum256()` · 流式 `sha256.New()` · 无需参数
- **适用场景**：文件校验、数字签名、HMAC、区块链、Merkle Tree

✅ **优点**：安全成熟 · 性能高 · 标准库支持
⚠️ **风险**：可被 GPU 高速计算 · 彩虹表攻击 · 直接存密码容易泄露
❗ **限制**：计算快、无 salt 机制，不具备密码存储需要的慢计算特性
🔁 **替代**：SHA-512（更长摘要）、Argon2id（密码场景）

> [!WARNING] **只做摘要与完整性校验，不要用来存密码。**

---

### 💀 MD5 — 经典通用哈希算法

> **定义**：输出 128 bit 摘要的经典通用哈希算法。

- **核心作用**：快速生成数据指纹，检测数据变化
- **解决的问题**：检测传输错误、文件一致性
- **基本原理**：`数据填充 → 512 bit 分组 → 4 轮压缩 → 输出 128 bit 摘要`
- **API**：`md5.Sum()` · 流式 `md5.New()` · 无需参数
- **适用场景**：文件快速校验、缓存 Key、数据去重

✅ **优点**：速度快 · 实现简单 · 兼容性强
⚠️ **风险**：已存在实际碰撞攻击 · 可构造相同 Hash 不同内容 · 不可用于安全认证
❗ **限制**：输出短、安全性不足 · 无法防御篡改攻击
🔁 **替代**：SHA-256、SHA-3、HMAC-SHA256

> [!CAUTION] 已不满足现代安全要求，**仅限非安全场景**。

---

## 分类总结

### 🧂 密码存储算法

> 目标：**提高密码破解成本** —— 让每次校验足够慢、足够吃内存。

- 🥇 **Argon2id** — 新系统首选，抗 GPU/ASIC 最强
- 🥈 **bcrypt ≈ scrypt** — 存量系统默认，生态成熟、可平滑升级
- 🥉 **PBKDF2** — FIPS/合规兜底，需保证足够高的迭代次数

### 📊 通用哈希算法

> 目标：**数据摘要与完整性校验** —— 速度优先、无需刻意变慢。

- ⚡ **SHA-256** — 文件校验、数字签名、HMAC、区块链
- 💀 **MD5** — 快速指纹、缓存 Key、数据去重（已存在碰撞攻击）

> [!CAUTION] **禁止用于密码存储**：MD5、SHA-256 计算过快，无法抵抗 GPU 破解。
