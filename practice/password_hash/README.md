### bcrypt

**定义和核心作用：** bcrypt 是自适应单向哈希算法（Adaptive Password Hash），不可逆，常用于用户密码生成哈希后存储持久化。

**解决什么问题：** 解决用户密码等不可公开信息的存储问题；哈希不可逆、破解成本高（取决于密码强度，随机复杂字符集可大大提高破解成本，过于简单的密码可用穷举、字典、用户信息组合破解）。

**基本原理和流程：** `$2a$10$4l1rFD3gAYCBU6IDKEnhPuRXZegZTtqMg8.5AlJLoBSScl4vyTJsy`

- `$2a$`：bcrypt 版本
- `10`：cost 成本
- `4l1rFD3gAYCBU6IDKEnhPu`：salt，22 个字符
- `RXZegZTtqMg8.5AlJLoBSScl4vyTJsy`：校验结果，31 个字符

生成流程：标记版本号 → 设置 cost（密码扩展级别）→ 生成随机 salt（22 个字符）→ 计算输出 31 个字符的哈希结果。

**API、配置和示例：** `GenerateFromPassword` 生成哈希，`CompareHashAndPassword` 比较密码哈希；cost 越大越耗时、越安全（默认 10）。

**适用场景、限制和风险：** 根据密码生成不可逆哈希，提高破解成本，杜绝彩虹表批量匹配；限制是哈希暴露后仍可能被彩虹表/暴力破解；不能解决弱密码暴露后的暴力破解。

**优缺点及替代方案：** 优点（生态成熟、兼容性好，旧哈希可继续验证）；缺点（增加接口延迟、DoS 风险，不能解决弱密码、撞库和在线暴力破解）；替代方案：Argon2id（存在迁移成本）。

**示例代码：** [bcrypt/index.go](bcrypt/index.go)

### Argon2id

**定义和核心作用：** Argon2id 是内存困难型密码哈希函数（Memory-Hard Password Hash），2015 年密码哈希竞赛冠军，RFC 9106 标准；核心作用是给密码生成带随机盐、高计算成本（CPU + 内存）的哈希，用于密码的安全存储与校验。

**解决什么问题：** 解决密码明文存储泄露问题，抵御彩虹表/预计算攻击与 GPU/ASIC 并行暴力破解；相比 bcrypt、PBKDF2 增加“内存困难”维度，攻击者的并行破解成本大幅上升。

**基本原理和流程：** `$argon2id$v=19$m=65536,t=1,p=4$<base64盐>$<base64哈希>`

流程：BLAKE2b 生成 H0 → 按 p 条 lane 并行填充 m 块内存（每块 1024 字节）→ 迭代 t 轮（每轮 4 个 slice 同步点）→ 末尾 XOR 合并各 lane → 提取 keyLen 字节密钥。

**API、配置和示例：** `argon2.IDKey` 生成哈希，`crypto/rand.Read` 生成随机盐，`crypto/subtle.ConstantTimeCompare` 常数时间比较；推荐参数 time=1、memory=64MiB、threads=4、keyLen=32（RFC 9106）。

**适用场景、限制和风险：** 适用用户密码存储等高安全场景；限制是内存参数依赖硬件，高并发校验会放大内存与 CPU 开销，移动端/低内存设备需调低参数；风险是参数过低不安全、不能解决弱密码与在线暴力破解、存在 DoS 风险。

**优缺点及替代方案：** 优点（内存困难抗 GPU/ASIC、自动加盐、参数自描述可平滑升级、RFC 9106 标准、常数时间比较）；缺点（内存占用大、单次计算较慢、生态兼容性不如 bcrypt）；替代方案：bcrypt（生态成熟、仅 CPU 成本）、scrypt（内存困难）、PBKDF2（标准成熟、无内存困难）；Argon2id 综合最优，切换需考虑旧哈希迁移成本。

**示例代码：** [argon2id/index.go](argon2id/index.go)

### scrypt

**定义和核心作用：** scrypt 是内存困难型密码派生函数（Memory-Hard PBKDF），由 Colin Percival 设计，通过消耗大量内存增加破解成本；核心作用是给密码派生带随机盐、高成本的密钥，用于密码的安全存储与校验。

**解决什么问题：** 解决密码明文存储泄露问题，抵御 GPU/ASIC 并行暴力破解与彩虹表攻击；相比 PBKDF2 增加“内存困难”维度，让专用硬件的并行破解成本大幅上升。

**基本原理和流程：** `$scrypt$N=32768,r=8,p=1$<base64盐>$<base64哈希>`

流程：密码 + 随机盐 → PBKDF2-HMAC-SHA256 预展开 → 大规模内存填充与反复读写（ROMix，占用约 128×N×r 字节内存）→ 再经 PBKDF2-HMAC-SHA256 输出 keyLen 字节密钥。

**API、配置和示例：** `scrypt.Key` 派生密钥，`crypto/rand.Read` 生成随机盐，`crypto/subtle.ConstantTimeCompare` 常数时间比较；推荐参数 N=32768, r=8, p=1, keyLen=32。

**适用场景、限制和风险：** 适用密码存储、加密文件系统等资源受限场景；限制是内存参数依赖硬件，N 过大会导致单次计算内存与耗时过高；风险是参数过低不安全、不能解决弱密码与在线暴力破解、存在 DoS 风险。

**优缺点及替代方案：** 优点（内存困难抗 GPU/ASIC、自动加盐、哈希串自带参数可解析重算）；缺点（会被侧信道攻击，内存占用大，高并发下成本高，参数需按硬件调优）；替代方案：Argon2id（综合最优）、PBKDF2（无内存困难）、bcrypt（仅 CPU 成本）。

**示例代码：** [scrypt/index.go](scrypt/index.go)

### PBKDF2

**定义和核心作用：** PBKDF2 是基于迭代次数的密码派生函数（RFC 8018 / PKCS #5 v2.1），通过反复迭代 HMAC 散列（如 HMAC-SHA256）把密码扩展为带盐的高成本密钥；核心作用是给密码生成高计算成本的哈希，用于密码的安全存储与校验。

**解决什么问题：** 解决密码明文存储泄露问题，通过迭代增加单次计算耗时，显著拖慢离线暴力破解；但本身不消耗内存，GPU/ASIC 并行破解成本相对较低。

**基本原理和流程：** `$pbkdf2-sha256$i=600000$<base64盐>$<base64哈希>`

流程：密码 + 随机盐 → HMAC-SHA256 迭代 i 次（首轮加盐，后续轮依赖前一轮结果）→ 生成 keyLen 字节密钥；块数按 keyLen/散列输出长度向上取整，各块独立派生后拼接。

**API、配置和示例：** `pbkdf2.Key` 派生密钥，`crypto/rand.Read` 生成随机盐，`crypto/subtle.ConstantTimeCompare` 常数时间比较；推荐迭代 600000 次、keyLen=32、散列函数选 SHA-256。

**适用场景、限制和风险：** 适用密码存储、密钥派生等标准场景（FIPS 认可、兼容性好）；限制是本身不消耗内存，专用硬件可并行破解；风险是迭代次数过低不安全、不能解决弱密码与在线暴力破解、存在 DoS 风险。

**优缺点及替代方案：** 优点（标准成熟 RFC 8018、兼容性好、可调迭代次数、无需大量内存）；缺点（无内存困难，专用硬件破解成本低）；替代方案：Argon2id / scrypt（内存困难）、bcrypt（仅 CPU 成本）。

**示例代码：** [pbkdf2/index.go](pbkdf2/index.go)

### SHA-256

**定义和核心作用：** SHA-256 是通用哈希函数（Secure Hash Algorithm 2 系列），输入任意长度数据，输出固定 256 位（32 字节、64 个十六进制字符）摘要；核心作用是数据完整性校验、消息摘要、数字签名与 HMAC 底层，不适合直接存密码。

**解决什么问题：** 解决数据完整性校验问题（检测数据被篡改或传输损坏），并提供单向、抗碰撞的摘要用于签名等场景；不能直接解决密码存储问题，因为速度快且无盐，易被 GPU 并行暴力破解与彩虹表攻击。

**基本原理和流程：** `$2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824`（"hello" 的 SHA-256）

流程：数据按 512 位分组并填充补位（末尾附加 64 位长度）→ 每分组经 64 轮压缩函数（基于 32 位字与 K 常量）→ 与 8 个 32 位初始哈希值累加 → 输出固定 256 位摘要。

**API、配置和示例：** `crypto/sha256.Sum256` 一次性计算，`sha256.New()` 流式接口（Write 分块写入、Sum 取摘要），`hex.EncodeToString` 输出 64 个十六进制字符；无需配置参数。

**适用场景、限制和风险：** 适用文件校验、消息摘要、Merkle 树、HMAC、数字签名等；限制是速度快且无盐，不抗 GPU 并行破解与彩虹表，不能直接用于密码存储；SHA-1/MD5 已被证明存在碰撞攻击，SHA-256 目前仍被认为是安全的。

**优缺点及替代方案：** 优点（输出固定、抗碰撞、标准成熟、标准库原生支持）；缺点（速度快且无盐，不适合密码存储）；替代方案：密码存储使用 bcrypt / Argon2id / scrypt / PBKDF2 等慢速加盐算法，更高强度摘要可用 SHA-384 / SHA-512。

**示例代码：** [sha256/index.go](sha256/index.go)

### MD5

**定义和核心作用：** MD5 是通用哈希函数（Message-Digest Algorithm 5），输入任意长度数据，输出固定 128 位（16 字节、32 个十六进制字符）摘要；核心作用是快速校验数据完整性（如文件是否被篡改、传输是否损坏），不能用于密码存储。

**解决什么问题：** 解决非关键数据的完整性校验问题，可快速发现数据被改动或传输出错；不能解决密码存储问题，因为速度快且无盐，已证实存在碰撞攻击，可被彩虹表/暴力破解。

**基本原理和流程：** `$5eb63bbbe01eeed093cb22bb8f5acdc3`（"hello world" 的 MD5 摘要）

流程：数据按 512 位分组并填充补位（末尾附加 64 位长度）→ 每分组做 4 轮 16 步压缩函数 → 与 4 个 32 位链接变量累加 → 输出固定 128 位摘要。

**API、配置和示例：** `crypto/md5.Sum` 一次性计算，`md5.New()` 流式接口（Write 分块写入、Sum 取摘要），`hex.EncodeToString` 输出 32 个十六进制字符；无需配置参数。

**适用场景、限制和风险：**

- 适用场景：文件完整性校验、快速生成内容指纹，非安全场景下的去重、缓存键、数据一致性检查。
- 限制和风险：已被证明存在严重碰撞漏洞，不适合数字签名、证书等安全用途；计算速度快，容易被暴力破解和彩虹表攻击；不能用于密码存储，即使加盐也不推荐，密码应使用 Argon2id、bcrypt 或 scrypt；MD5 只能发现普通传输错误，无法抵御攻击者恶意篡改，需要防篡改时应使用 HMAC-SHA256。

**优缺点及替代方案：** 优点（速度快、实现简单、输出固定长度）；缺点（存在碰撞攻击、无盐、不抗彩虹表）；替代方案：SHA-256（安全的完整性校验），密码存储使用 bcrypt / Argon2id / scrypt / PBKDF2 等慢速加盐算法。

**示例代码：** [md5/index.go](md5/index.go)
